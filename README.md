# Be My Cupid (DAM)

An AI dating matchmaker built with Next.js and the Vercel AI SDK. DAM walks you through a short preference intake, then generates partner profiles you can swipe through and save.

Originally a college project; maintained as a portfolio showcase.

## Features

- Conversational intake form + chat refinement
- AI-generated partner profiles (close / stretch / exploratory matches)
- Optional AI headshots
- In-chat swipe UI to save or pass matches
- Hybrid persistence: works with guest + `localStorage`, or Postgres when configured
- Google Gemini via the AI SDK

## Stack

- Next.js (App Router) + React 19
- AI SDK + `@ai-sdk/google`
- Auth.js (credentials + guest)
- Drizzle ORM + Postgres (optional)
- Tailwind CSS / shadcn-style UI

## Environment

Copy [`.env.example`](.env.example) to `.env.local` and fill in values:

| Variable | Required | Purpose |
|----------|----------|---------|
| `GOOGLE_GENERATIVE_AI_API_KEY` | Yes | Gemini text + image |
| `AUTH_SECRET` | Yes | Auth.js session cookies |
| `POSTGRES_URL` | No | Chat history, users, saved matches |
| `BLOB_READ_WRITE_TOKEN` | No | File / photo uploads via Vercel Blob |
| `REDIS_URL` | No | Resumable chat streams |
| `NANO_BANANA_IMAGE_MODEL` | No | Override image model id |

Without `POSTGRES_URL`, the app still runs: guests are created locally and saved matches fall back to `localStorage`.

Generate an auth secret if needed:

```bash
openssl rand -base64 32
```

## Running locally

```bash
pnpm install
pnpm db:migrate   # only needed when POSTGRES_URL is set
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000). Unauthenticated visitors are signed in as guests automatically.

## Deploy on Render

The repo includes a [`render.yaml`](render.yaml) Blueprint.

1. Push this repo to GitHub.
2. In [Render](https://dashboard.render.com): **New → Blueprint** → select the repo (or **New → Web Service** and use the build/start commands below).
3. Set environment variables:
   - `GOOGLE_GENERATIVE_AI_API_KEY` (required)
   - `AUTH_SECRET` (auto-generated by the Blueprint, or set yourself)
   - `AUTH_URL` = your public URL after deploy (e.g. `https://be-my-cupid.onrender.com`)
   - `AUTH_TRUST_HOST=true` (already set in the Blueprint)
   - Optional: `POSTGRES_URL` if you want DB persistence (Render Postgres or Neon)
4. Deploy. Health check path: `/ping`.

**Manual Web Service settings** (if not using the Blueprint):

| Setting | Value |
|---------|--------|
| Runtime | Node |
| Build | `npx pnpm@9.12.3 install --frozen-lockfile && npx pnpm@9.12.3 build` |
| Start | `npx pnpm@9.12.3 start` |
| Health check | `/ping` |

Free-tier instances may spin down when idle; the first request after sleep can take ~30–60s.

## Project structure

```
app/
  (app)/           # Matchmaker pages (home, chat, saved)
  api/             # HTTP routes (auth, chat, matches, …)
  login/ register/ # Auth pages
components/
  matchmaker/      # Intake, profile cards, saved matches
  chat/            # Chat shell, messages, input, header
  ui/ elements/    # Shared primitives
lib/
  auth/            # Auth.js config + actions
  ai/              # Prompts, models, tools (prompt text lives here)
  matches/         # Shared saved-match types + localStorage helpers
  chat/            # Chat visibility + history helpers
  db/              # Schema, queries, migrations
scripts/
  gemini-smoke/    # Manual Gemini API smoke tests
```
